# 무료 운영과 장애 대응

월 0원을 목표로 GitHub 공개 저장소 Pages와 Supabase Free를 사용합니다. 실제 생성한 Supabase 조직의 plan=free, 프로젝트 ACTIVE_HEALTHY와 서울 리전을 확인했습니다. 사용량 증가나 정책 변경 시 계속 무료라고 보장하지 않습니다. 자동 유료 업그레이드는 하지 않습니다.

- Supabase Free는 낮은 활동이 약 7일 지속되면 프로젝트를 일시 중지할 수 있습니다. 이때 DB/Auth/Edge/Cron이 동작하지 않아 동기화와 Push가 지연됩니다. Dashboard에서 재개한 후 오류·오래된 알림을 확인하세요.
- DB 크기, egress, MAU, Edge 호출, 스토리지, 활성 무료 프로젝트 수에는 각 제한이 있습니다. [현재 요금·쿼터](https://supabase.com/pricing)를 Dashboard와 함께 확인하세요. 무료 자동 백업·상시 가동·Push 정시 도착을 약속하지 않습니다.
- Pages는 정적 호스팅입니다. API secret을 빌드에 넣으면 공개됩니다. Actions 분량·저장 공간·배포 제한은 GitHub 정책에 따릅니다.
- GitHub 예약 작업은 지연·누락될 수 있고 공개 저장소는 장기간 활동이 없으면 예약 실행이 비활성화될 수 있습니다. 매월 holiday workflow와 fetchedAt을 확인하고 수동 실행하세요.
- Push는 OS 절전·권한·브라우저·네트워크에 영향을 받습니다. iOS는 호환 버전의 홈 화면 PWA에서 사용하세요. 거부·미지원 시 앱 내부 알림을 사용합니다. Cron이 5분 주기이므로 수분 지연이 정상적으로 생길 수 있습니다.
- 오프라인 변경은 브라우저 저장 공간에 있습니다. 동기화 전에 브라우저 데이터를 지우거나 로그아웃하면 대기 데이터가 사라질 수 있습니다. 먼저 동기화 또는 JSON 백업하세요.

## 점검

매 배포: CI, 실URL, 로그인, SW 업데이트, 오류 상태 확인. 매주: Supabase pause 상태, Edge/Cron 실패, notification_jobs와 기기별 deliveries의 실패 상태, 사용량 확인. 매월: 공식 공휴일 갱신과 예약 workflow 활성 상태. 분기: JSON 복원 리허설, 종속성 audit, 무료 정책 재확인.

DB 장애는 캐시를 삭제해 해결하지 않습니다. 대기 큐를 보존하고 연결을 복구한 뒤 재시도합니다. 버전 충돌은 서버/내 변경을 비교해 선택합니다. 전체 교체 복원 전에는 현재 데이터를 별도 JSON으로 내보내세요.

VAPID 키를 잃거나 회전하면 기기를 재구독합니다. service role/Google secret/공휴일 키가 노출되면 해당 공급자에서 즉시 폐기·재발급하고 배포 이력과 로그를 확인합니다. private key를 프런트에서 재생성해 복구하지 않습니다.
